# Apple Health API

Python Azure Function that accepts Apple Health exports from the React Native app and stores each payload in Azure Cosmos DB for NoSQL.

## Endpoint

`POST /api/health-export`

The request body should match the app payload:

```json
[
  {
    "type": "apple-health-data",
    "user_id": "Jack",
    "date": "2026-05-04",
    "active_energy_kcal": 642,
    "exercise_minutes": 48,
    "stand_hours": 11
  },
  {
    "type": "apple-health-data",
    "user_id": "Jack",
    "date": "2026-05-03",
    "active_energy_kcal": 501,
    "exercise_minutes": 32,
    "stand_hours": 10
  }
]
```

A single row object is also accepted, but the app normally sends a list. If `type` is omitted, the API stores the row as `apple-health-data`.

Successful response:

```json
{
  "ok": true,
  "count": 2,
  "ids": [
    "apple-health-data::Jack::2026-05-04",
    "apple-health-data::Jack::2026-05-03"
  ]
}
```

## Missing Dates

`GET /api/health-export?action=missing-dates&user_id=Jack&startDate=2026-01-01&endDate=2026-05-02`

This checks Cosmos DB for existing daily rows for the requested user and returns the local dates that are not present. `startDate` and `endDate` are inclusive.

Successful response:

```json
{
  "missingDates": ["2026-04-29", "2026-05-01"]
}
```

## Cosmos DB shape

Each daily row is stored as one document. The document keeps the row fields and adds:

- `id`: `apple-health-data::<user_id>::<date>`
- `type`: `apple-health-data`
- `userID`: copied from `user_id` for compatibility with existing raw-data partitioning
- `receivedAt`: UTC timestamp generated by the API

Using a stable document ID means retries and repeated exports for the same user and date update the existing document instead of creating duplicates. The API stores both `user_id` and `userID`, so the raw-data container can be partitioned by either field. Missing-date checks filter on `type = "apple-health-data"`, so other health sources can share the same container.

## App settings

Copy `local.settings.json.sample` to `local.settings.json` for local development and fill in:

- `COSMOS_ENDPOINT`
- `COSMOS_KEY`
- `COSMOS_DATABASE`
- `COSMOS_CONTAINER`
- `COSMOS_COMPETITION_CONTAINER`, defaults to `fitness_competitions`
- `HEALTH_API_TOKEN`, optional. If set, requests must include `Authorization: Bearer <token>`. Missing or invalid bearer tokens return `403`.

In Azure, add the same keys under Function App > Settings > Environment variables.

## Competition API

The competition API uses the same bearer token as the health export endpoint. Documents are stored in the Cosmos container named by `COSMOS_COMPETITION_CONTAINER`, normally `fitness_competitions`.

### Users

`POST /api/users`

```json
{
  "userID": "Jack",
  "displayName": "Jack",
  "timezone": "Europe/London",
  "goalWeightKg": 87,
  "averageDailyCalorieTarget": 2400,
  "active": true,
  "syncSources": {
    "renpho": {
      "enabled": true,
      "credentialRef": "jack"
    },
    "fatsecret": {
      "enabled": true,
      "credentialRef": "jack"
    },
    "appleHealth": {
      "enabled": true
    }
  }
}
```

Creates or upserts a user document with deterministic `id`, for example `user_jack`.

If `syncSources` is omitted when creating a user, the API enables Renpho and FatSecret by default and sets each `credentialRef` to the normalised lowercase `userID`, for example `Jack` becomes `jack`. Apple Health is also enabled by default.

`syncSources` stores safe metadata only. The API rejects fields that look like passwords, tokens, API keys, client secrets, access secrets, connection strings, or Function App setting names. `credentialRef` must be a short safe identifier such as `jack` or `ash`; it is not a secret. If `renpho.enabled` or `fatsecret.enabled` is `true`, that source must include `credentialRef`.

Other user endpoints:

- `GET /api/users`
- `GET /api/users/{user_id}`
- `PATCH /api/users/{user_id}`
- `PATCH /api/users/{user_id}/sync-sources`
- `GET /api/users/{user_id}/profile-check`

Example sync-source patch:

```json
{
  "renpho": {
    "enabled": false,
    "credentialRef": "ash"
  },
  "fatsecret": {
    "enabled": false,
    "credentialRef": "ash"
  },
  "appleHealth": {
    "enabled": true
  }
}
```

This backend does not access Renpho or FatSecret directly and does not store their passwords, tokens, API secrets, or Azure Function setting names.

Other challenge endpoints:

- `GET /api/challenges/current-or-upcoming`
- `GET /api/challenges/{challenge_id}`
- `PATCH /api/challenges/{challenge_id}`
- `GET /api/challenges/{challenge_id}/settings`

Challenge responses include `rules`, `participantProfiles` where useful, and `forfeits` as an object keyed by `weekly`, `monthly`, and `championship`. If the stored challenge has `forfeits`, responses also include `forfeitDetails` as an app-friendly alias. If a stored challenge has no `rules`, the API returns default display rules.

### Participants

`POST /api/challenges/{challenge_id}/participants`

```json
{
  "userID": "Jack",
  "active": true
}
```

Adding a participant upserts a `challenge_participant` document and ensures the challenge `participants` array includes the user ID. Deleting a participant marks the participant inactive and removes the user ID from the challenge array.

Participant endpoints:

- `GET /api/challenges/{challenge_id}/participants`
- `POST /api/challenges/{challenge_id}/participants`
- `PATCH /api/challenges/{challenge_id}/participants/{user_id}`
- `DELETE /api/challenges/{challenge_id}/participants/{user_id}`

### App Helpers

- `GET /api/app/bootstrap?user_id=Jack`: returns the current user profile plus the active or next upcoming challenge.
- `GET /api/challenges/{challenge_id}/leaderboards/latest?kind=week`
- `GET /api/challenges/{challenge_id}/leaderboards?kind=week`
- `GET /api/challenges/{challenge_id}/scores?userID=Jack`

Latest leaderboard `kind` may be `week`, `month`, `final`, or `current`. If no latest leaderboard exists, the API returns `200` with an empty `rows` array. The app uses `kind=week` as its running tally request, and an empty response has `kind: "current"` and `periodLabel: "Running tally"`.

Leaderboard history can be requested without a `kind` query:

`GET /api/challenges/{challenge_id}/leaderboards`

This returns previous `week`, `month`, and `final` leaderboards:

```json
{
  "leaderboards": [
    {
      "leaderboardID": "lb_week_1",
      "challengeID": "challenge_2026_05_04",
      "kind": "week",
      "periodLabel": "Week 1",
      "periodStart": "2026-05-04",
      "periodEnd": "2026-05-10",
      "generatedAt": "2026-05-11T00:05:00Z",
      "rows": []
    }
  ]
}
```

## Deploy

From this folder:

```bash
func azure functionapp publish <function-app-name>
```

Use the deployed function URL in the React Native app. If `HEALTH_API_TOKEN` is set, also enter that token in the app so it sends the bearer header.
