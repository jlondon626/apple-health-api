# Apple Health API

Python Azure Function that accepts Apple Health exports from the React Native app and stores each payload in Azure Cosmos DB for NoSQL.

## Endpoint

`POST /api/health-export`

The request body should match the app payload:

```json
[
  {
    "type": "apple-health-data",
    "user_id": "Jack",
    "date": "2026-05-04",
    "active_energy_kcal": 642,
    "exercise_minutes": 48,
    "stand_hours": 11
  },
  {
    "type": "apple-health-data",
    "user_id": "Jack",
    "date": "2026-05-03",
    "active_energy_kcal": 501,
    "exercise_minutes": 32,
    "stand_hours": 10
  }
]
```

A single row object is also accepted, but the app normally sends a list. If `type` is omitted, the API stores the row as `apple-health-data`.

Successful response:

```json
{
  "ok": true,
  "count": 2,
  "ids": ["Jack:2026-05-04", "Jack:2026-05-03"]
}
```

## Missing Dates

`GET /api/health-export?action=missing-dates&user_id=Jack&startDate=2026-01-01&endDate=2026-05-02`

This checks Cosmos DB for existing daily rows for the requested user and returns the local dates that are not present. `startDate` and `endDate` are inclusive.

Successful response:

```json
{
  "missingDates": ["2026-04-29", "2026-05-01"]
}
```

## Cosmos DB shape

Each daily row is stored as one document. The document keeps the row fields and adds:

- `id`: `<user_id>:<date>`
- `type`: `apple-health-data`
- `userID`: copied from `user_id` for the Cosmos partition key
- `receivedAt`: UTC timestamp generated by the API

Create the Cosmos container with partition key `/userID`. Using a stable document ID means retries and repeated exports for the same user and date update the existing document instead of creating duplicates. Missing-date checks filter on `type = "apple-health-data"`, so other health sources can share the same container.

## App settings

Copy `local.settings.json.sample` to `local.settings.json` for local development and fill in:

- `COSMOS_ENDPOINT`
- `COSMOS_KEY`
- `COSMOS_DATABASE`
- `COSMOS_CONTAINER`
- `HEALTH_API_TOKEN`, optional. If set, requests must include `Authorization: Bearer <token>`.

In Azure, add the same keys under Function App > Settings > Environment variables.

## Local development

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
func start
```

If Core Tools starts with `No module named 'azure.cosmos'` on Windows, run it with the virtualenv packages on `PYTHONPATH`:

```bash
$env:PYTHONPATH = "$PWD\.venv\Lib\site-packages"
func start
```

Health check:

```bash
curl http://localhost:7071/api/status
```

Example post:

```bash
curl -X POST http://localhost:7071/api/health-export ^
  -H "Content-Type: application/json" ^
  -H "Authorization: Bearer <token>" ^
  -d "[{\"type\":\"apple-health-data\",\"user_id\":\"Jack\",\"date\":\"2026-05-04\",\"active_energy_kcal\":642,\"exercise_minutes\":48,\"stand_hours\":11}]"
```

Example missing-date lookup:

```bash
curl "http://localhost:7071/api/health-export?action=missing-dates&user_id=Jack&startDate=2026-01-01&endDate=2026-05-02" ^
  -H "Authorization: Bearer <token>"
```

## Deploy

From this folder:

```bash
func azure functionapp publish <function-app-name>
```

Use the deployed function URL in the React Native app. If `HEALTH_API_TOKEN` is set, also enter that token in the app so it sends the bearer header.

## References

- Azure Functions Python v2 uses decorators in `function_app.py`.
- Azure Cosmos DB Python SDK supports `container.upsert_item(...)` for insert-or-update writes.
